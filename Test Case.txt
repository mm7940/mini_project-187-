Test Case 1 — Client debit party, Multileg = No
Test Case
1. Login to the CERS system.
2. Submit a valid US ROF compliance return message containing a configured AML FYI keyword.
3. Ensure the debit party is identified as a client.
4. Set the Multileg flag to No.
5. Allow the system to process the message.
6. Open the created case and verify the Work Info tab and STP Info.
Expected Results
1. The case should be created as Return of Funds with the AML FYI indicator.
2. The debit party should be identified as a client.
3. The ROF STP flow should continue.
4. The case should not be moved to SBS based solely on the AML FYI indicator.
5. The Work Info and STP Info should reflect the expected processing flow.
Actual Results
To be updated after test execution.




Test Case 2 — Non-client debit party, Multileg = No
Test Case
1. Login to the CERS system.
2. Submit a valid US ROF compliance return message containing a configured AML FYI keyword.
3. Ensure the debit party is identified as a non-client (for example, a Chip or Fed Bank scenario).

Expected Results

4. The ROF STP flow should be revoked.
5. The STP exception reason should display Debit Party is Non-Client.
6. The Work Info and STP Info should reflect the expected processing flow.
